# Releasing Hermes Glasses (TestFlight via fastlane)

`fastlane/README.md` is generated by fastlane (lane list only); this page is the how-to. The setup mirrors
Tool Approvals (`~/Development/hermes-tool-approvals/ios/fastlane`): same App Store Connect API key, same
match repository (`ejlevin1/aapi-match-certs`), same `approvals-signing` keychain, team `6MPMD6S5U9`,
bundle id `me.ericlevin.hermesglasses`.

**Read `~/Development/hermes-tool-approvals/ios/docs/BUILD_MACHINE.md` before any signing work.** Its hazards
apply unchanged here: keychain order (approvals-signing first), match minting certificates on a
`readonly: false` run, and mbp-m2 having no global git identity.

## One-time setup (build machine)

```bash
export PATH="/opt/homebrew/opt/ruby/bin:$PATH"   # Homebrew Ruby, never system Ruby 2.6
bundle config set --local path vendor/bundle
bundle install
```

Secrets, none of them in git:

| What | Where | Used by |
|---|---|---|
| Meta DAT app id + client token | `~/Development/.env/hermes-glasses-secrets.xcconfig` (or `$HERMES_GLASSES_SECRETS`), copied to `Config/Secrets.xcconfig` by `scripts/write_secrets.sh` | build |
| ASC API key, match passphrase, certs-repo token | `~/Development/.env/approvals-fastlane` | `certs`, `beta` |
| signing keychain name + password | `~/Development/.env/approvals-keychain` | `certs`, `beta` |
| ASC app record id | `APPLE_ID` constant in `fastlane/Fastfile` (6830498208); env `ASC_APP_ID` overrides | `beta` upload |

The Fastfile reads those files itself (environment first, then `fastlane/.env.local`, then the machine
files), so no `set -a; . …` preamble is needed. Only variable *names* are ever logged.

## Lanes

| Lane | What it does | Signing |
|---|---|---|
| `bundle exec fastlane test` | unsigned simulator build + every standalone Swift suite (`scripts/run_swift_tests.sh`) | none |
| `bundle exec fastlane certs` | match `appstore` (+ `development` with `MATCH_DEVELOPMENT=1`), read-only | reads |
| `MATCH_READONLY=0 bundle exec fastlane certs` | **one time only**: creates the profiles for this new app id, reusing the existing certificates (distribution `ZBZU9783S4`, development `76B22RR6W7`). Abort if match says it is generating a certificate. Never `match nuke`. | writes |
| `bundle exec fastlane beta skip_upload:true` | secrets → icon check → keychain unlock → match (read-only) → build number = latest TestFlight + 1 → signed Release archive + app-store export → IPA check. Stops before upload. IPA at `build/HermesGlasses.ipa`. | reads |
| `bundle exec fastlane beta` | the same, then `upload_to_testflight` (internal only, `skip_waiting_for_build_processing`) | reads |
| `bundle exec fastlane beta build_number:<n>` | the same with an explicit build number (must exceed the latest TestFlight build); use it after Apple rejects an upload in processing, because a rejected upload never becomes a build but its number stays taken | reads |

The IPA check asserts, on the signed artefact: the Hotspot Configuration + Wi-Fi Info entitlements, the
computed `CFBundleVersion`, and that the Meta DAT credentials were substituted (not the `0` placeholder).

## How signing and versioning are wired

- **Release** is manually signed in the project (iphoneos only): `Apple Distribution` +
  `match AppStore me.ericlevin.hermesglasses`. Debug stays Automatic for Xcode cable installs. Signing is not
  overridden through `xcargs`, because an xcargs `PROVISIONING_PROFILE_SPECIFIER` also lands on the SwiftPM
  targets and fails the build.
- **Build number:** `Info.plist` `CFBundleVersion` is `$(CURRENT_PROJECT_VERSION)`; `beta` passes
  `CURRENT_PROJECT_VERSION=<latest TestFlight + 1>` to xcodebuild. Nothing is written into the tree (no
  `agvtool`, which would replace the indirection with a literal).
- `ITSAppUsesNonExemptEncryption = NO`, so uploads do not stop at export compliance.

## Before the first upload

The App Store Connect app record for `me.ericlevin.hermesglasses` must exist (Eric creates it; the ASC API
cannot). Without it `latest_testflight_build_number` and the upload fail.
